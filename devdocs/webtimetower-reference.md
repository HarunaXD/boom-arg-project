# 《网络时光塔》参考拆解与设计经验

调研日期：2026-06-17  
参考入口：https://spectrum.shiroki-y2.top/webtimetower.html

本文记录从《网络时光塔 (Web Time Tower)》中可吸收的 ARG / 网页解谜设计经验，供本项目后续 Archive 系列设计参考。以下内容侧重机制和设计原则，不复刻其具体剧情、美术素材或谜题答案。

## 一、总体结构观察

《网络时光塔》的外层是一个伪网页存档服务。玩家在首页输入网址后，进入被存档的旧网站页面；旧网站又继续导向新闻页、专栏页、搜索结果页、外部伪论坛和隐藏页面。它的核心不是“一个谜题页面”，而是一个由网页历史、站内搜索、访问记录和跨站链接构成的档案迷宫。

值得借鉴的结构：

| 层级 | 表面功能 | 实际游戏作用 |
| --- | --- | --- |
| 网络时光塔首页 | 查询网页历史版本 | 建立“存档/时间/访问记录”的框架规则 |
| 2005 电视台站点 | 怀旧门户网站 | 放置新闻、节目、专栏、广告、搜索框等自然线索容器 |
| 2008 关站页面 | 历史版本对照 | 用时间差制造因果悬念 |
| 站内搜索 | 普通搜索 | 关键词门锁、禁词反馈、隐藏路由 |
| 外部伪论坛 | 合作论坛外链 | 扩展世界边界，制造“这不是单站点事件”的感觉 |
| 本地访问记录 | 历史列表 | 让玩家的探索痕迹变成界面内容 |

## 二、可吸收的设计经验

### 1. 用“可信工具”承载不可信内容

外层的网页存档服务非常有效，因为它天然解释了：

- 为什么玩家能访问不同年份的页面。
- 为什么页面会破损、缺图、跳转异常。
- 为什么旧网页里会有停用、404、数据丢失。
- 为什么访问历史会被记录。

对本项目的启发：Archive 系列可以继续把“浏览器工具”本身做成叙事装置。搜索、分页、收藏、历史记录、缓存、用户资料、文件夹、压缩包、邮件附件等，都比单独的“谜题面板”更有沉浸感。

### 2. 时间切片比单线叙事更适合网页 ARG

首页查询后给出两个时间点：2005 年的活跃站点和 2008 年的关站通知。玩家先看到一个热闹门户，再看到它的终止状态，会自然产生“中间发生了什么”的问题。

可复用原则：

- 早期页面负责铺设正常业务、人物关系和日常质感。
- 后期页面负责展示后果，但不要一次解释原因。
- 中间缺失的信息由玩家通过搜索、侧栏、外链和隐藏页补齐。

这比直接讲灾难更有后劲，因为玩家是在对照中发现异常。

### 3. 把怀旧网页的“低效率”变成探索节奏

旧门户、新闻站、论坛、广告条、滚动字幕、节目表、站内搜索、页脚链接都不是装饰；它们提供了大量可点击但不一定有用的区域。玩家会先像普通上网一样乱点，再逐渐学会判断哪些是线索。

可借鉴的节奏：

- 大量普通链接制造生活感。
- 少量有效链接藏在自然版位中，例如“阅读全文”“专栏”“合作论坛”。
- 无效链接不要静默失败，而是给统一反馈，例如“未收录”“已停止服务”。
- 让无效反馈也符合世界观，避免玩家以为是实现 bug。

### 4. 访问记录是低成本但高价值的玩家记忆

主脚本会把玩家访问过的非首页页面写入 `localStorage`，首页再显示“访问记录”。这让玩家的路径成为游戏界面的一部分。

对本项目的直接建议：

- 每个 Archive 游戏都可以有“浏览痕迹”系统，记录访问过的帖子、图片、档案或用户页。
- 访问记录不只做回访入口，也可以在后期发生污染：标题变短、时间错乱、重复出现、出现玩家没访问过的页面。
- 记录列表可以承担轻量提示功能：当玩家迷路时，旧路径本身就是线索地图。

### 5. 搜索框可以从工具升级为门锁

该游戏的旧电视台搜索框有两层设计：

- 第一层：需要先输入权限密钥 `3K7p-9xQ2-fS5d`，通过后才允许搜索。
- 第二层：搜索结果用 MD5 + Base64 后的关键词映射到页面，另有禁词配置触发隐藏文本、抖动、重定向或无限循环。

可吸收点不是加密本身，而是“搜索行为被剧情化”：

- 输入错误时不是普通报错，而是“权限保护”。
- 输入敏感词时页面状态改变，让玩家意识到系统在防御。
- 搜索结果可以通向普通资料页、外部论坛、隐藏目录或结局入口。

对本项目建议：搜索框应有明确阶段感。早期像普通检索，中期像权限系统，后期像敌对实体的监控接口。

### 6. 系统层反制能强化“网页在看你”

搜索结果页禁用了右键、查看源码和开发者工具快捷键，并弹出“逃避不能解决问题”。这不是安全措施，而是把玩家的破壁行为纳入叙事反馈。

借鉴时要谨慎：

- 可以拦截右键、复制、快捷键，但反馈要短、少、准。
- 不要真的阻止玩家太久，否则会变成操作挫败。
- 最好让反制本身成为提示：玩家越想绕过页面，页面越暴露它的意图。

### 7. 微交互机关不必复杂，但要和阅读动作绑定

专栏页中有一个滚动触发的图片替换：当目标图片完整进入视口后，玩家再次滚动会短暂替换图片。这个机关成本很低，但效果好，因为它利用了“读文章必然滚动”的动作。

可复用模式：

| 玩家自然动作 | 可绑定的异常 |
| --- | --- |
| 滚动读长文 | 图片闪变、段落重排、页眉报错 |
| 停留观看图片 | 噪点聚集、隐藏字浮现 |
| 返回首页 | 访问记录出现陌生项 |
| 搜索关键词 | 系统语气变化 |
| 点无效广告 | 顶部存档条反馈异常 |
| 选择问卷选项 | 只有某个选项得到“真实”响应 |

重点是让玩家觉得“我刚才正常浏览时好像看见了什么”，而不是明晃晃地按按钮解谜。

### 8. 用真实历史质感遮蔽虚构主线

2005 年门户页面借用了神舟六号、老式论坛、门户广告、节目表、滚动新闻等时代元素。玩家先接受“这像一个旧网站”，再在可信背景中发现未知文明、数字坐标、异常用户。

对本项目建议：

- 每个 Archive 项目都应先建立一个足够具体的时代与行业外壳。
- 恐怖线索应从行业内容内部长出来，而不是外挂一段恐怖文案。
- 广告、版权、浏览器建议、栏目时间表、过期活动，都可以作为时代锚点。

### 9. 跨站线索扩大世界，但要保留回流路径

旧电视台新闻页导向外部伪论坛，论坛又出现数字坐标、未知用户、楼层提示、图片符号等线索。这个设计让玩家感到世界不止一个网站。

需要注意：

- 外部站点必须有清楚的“来自存档系统”的页眉或返回方式，否则玩家会迷失。
- 外部站点的视觉风格应明显不同，但交互规则要和主站一致。
- 跨站线索最好回流到主站搜索框或某个隐藏目录，形成闭环。

### 10. 页码/总量可以制造未完成压力

首页标出 `01/45`，后续页面也有 `02/45`、`03/45`、`05/45`、`13/45`、`14/45`、`ex/45` 等页码。它暗示游戏存在一个可收集的总量，但不强制玩家按顺序浏览。

可借鉴方式：

- 用 `已归档条目 07/45`、`样本 12/30`、`用户记录 04/18` 这类轻量计数制造探索欲。
- 允许跳号和 `ex` 条目，让玩家意识到有隐藏页或外部档案。
- 不要把计数做成纯收集清单；它应服务于“档案不完整”的氛围。

## 三、可落地到本项目的具体设计清单

### A. Archive1001《阳光新村 BBS》

- 增加“浏览记录/最近访问帖子”模块，后期可被 UID 1001 污染。
- 让搜索框有阶段变化：普通搜索 → 系统警告 → 输入代号查看归档报告。
- 在户型图、物业公告、二手交易之间加入跨页面回流，而不只靠玩家记忆。
- 给无效链接统一世界观反馈，例如“离线归档未收录该资源”。
- 长帖中增加 1-2 个滚动触发或全选复制触发的微异常，增强“读档案”的身体感。

### B. Archive1002《Project-Æ 完美降临》

- 增加访问痕迹或检索日志，让玩家看到自己被系统记录。
- 终端/搜索框可加入禁词反馈：某些关键词不返回结果，而是改变页面状态。
- 精品店、粉丝榜、图库之间增加“旧版本/已下架页面”的时间对照。
- 对右键、保存图片、复制文本等浏览器原生动作给予少量叙事反馈。
- 隐藏 V1 归档页可以采用 `ex/总数` 计数，提示它不属于正常站点结构。

## 四、避免照搬的问题

- 不要依赖前端源码作为唯一解法。源码彩蛋可以存在，但主线应能通过玩家视角推理完成。
- 不要让搜索关键词全靠猜。每个关键词都应至少有两处自然铺垫。
- 不要让禁用右键/开发者工具成为真正阻碍。它应该是气氛反馈，不是反玩家设计。
- 不要过量堆旧网页元素。怀旧 UI 要服务信息层级，否则会让玩家疲劳。
- 不要把“45 个页面”当目标。页面数量不如线索密度和回流路径重要。

## 五、总结原则

《网络时光塔》最值得吸收的不是某个谜题，而是它把网页本身拆成了叙事机器：历史版本提供时间差，搜索框提供权限门锁，访问记录提供玩家记忆，外链提供世界扩张，无效链接和系统反制提供敌意反馈。

本项目后续设计可以遵循一句话原则：

> 让玩家以为自己在使用一个过时但可信的网站，然后逐步发现网站的每个普通功能都在参与叙事。
